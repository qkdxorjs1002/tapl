# Viewer·확장 UX 설계와 업그레이드 계획

[English](viewer-ux-design.md) · **한국어**

**통합 구성을 공유 Viewer에 적용했으며 갤러리는 합성 데이터 기반 설계 참고 자료입니다. 제품의 현재 동작은 [Viewer](../guides/viewer.ko.md)와 [VS Code 확장](../guides/vscode.ko.md)이 기준입니다.**

<a id="run-mindmap-concept"></a>

## RUN 마인드맵 시안

[독립 마인드맵 시안](../design/run-mindmap/index.html)은 중앙 RUN에서 PLAN 가지와 컴팩트한 TASK로 이어집니다. 노드를 호버하거나 선택하면 연결된 경로를 강조합니다. 드래그나 두 손가락 스크롤로 가로·세로 이동하고 핀치 위치를 기준으로 확대·축소합니다. 마우스 휠은 이동, Shift+휠은 수평 이동, Ctrl+휠은 확대·축소입니다. 터치 화면의 드래그·두 손가락 핀치와 Safari 제스처 이벤트를 각각 처리합니다. Escape 또는 중앙으로 버튼으로 복귀하며, 좁은 화면에서는 노드를 읽을 수 있는 크기로 유지하고 이동해 탐색합니다. 노드와 연결선은 감쇠된 스프링 반응으로 함께 움직입니다. 한영·라이트/다크·키보드 탐색과 모션 줄이기를 지원합니다.

모든 기록은 예시입니다. 실제 Viewer와 독립적으로 동작하며 워크스페이스나 워크플로를 수정하지 않습니다.

## 통합 시안

[통합 Viewer 시안](../design/viewer-workbench/index.html)은 RUN 정보·PLAN 요약, 02의 Flow 칸반과 01의 TASK 현황을 하나의 고정 셸로 결합합니다. [현재 RUN](../design/viewer-workbench/current-ko.png) · [Explore 상세](../design/viewer-workbench/explore-ko.png) · [탐색 확장 패널](../design/viewer-workbench/explore-panel-ko.png) · [통합 검색](../design/viewer-workbench/search-ko.png) · [영문·어두운 테마](../design/viewer-workbench/current-en-dark.png) 이미지에서도 확인할 수 있습니다.

| 영역 | 구성과 동작 |
| --- | --- |
| 상단 고정 바 | `tapl` 브랜드 영역 오른쪽에 언어·라이트/다크 아이콘을 나란히 정렬합니다. 언어 아이콘을 열어 한국어·English를 선택합니다. 여유 공간에 아카이브되지 않은 RUN의 제목·상태·ID로 구성한 네비게이션 탭을 배치하고 세션 문구는 표시하지 않습니다. 전환 시 선택한 RUN의 현황·Explore·관리 범위로 바뀝니다. 방향키·Home·End를 지원하고 탭이 많으면 탭 영역만 가로 스크롤합니다. |
| 좌측 상단 Workspace | 현재 RUN은 RUN 정보·PLAN 요약·Flow 칸반을 결합하며 메뉴 우측에 완료 TASK / 전체 TASK 비율을 반올림한 정수 %를 표시합니다(TASK가 없으면 0%). TASK 현황은 01을 바탕으로 한 전체 폭의 목록으로 구성합니다. TASK를 선택하면 Explore의 TASK 상세 페이지로 바로 이동하며 탐색 유형과 선택 항목도 맞춥니다. 현재 RUN·TASK 현황의 페이지 전환은 좌측 메뉴에서 제공하며 해당 본문 탭과 페이지 뎁스는 표시하지 않습니다. |
| 좌측 상단 Explore | PLAN·TASK·FINDING은 의미에 맞는 아이콘과 개수로 표시합니다. PC에서 호버·클릭하면 오른쪽 확장 패널 하나를 열고 트리거·패널을 벗어나면 닫습니다. 목록은 독립 스크롤하며 RUN·유형별 위치를 유지합니다. 항목 선택 시 본문 상세로 이동합니다. |
| 좌측 하단 Memory | 기록 검색과 연상 기억 페이지로 이동합니다. 기록 검색은 PLAN·TASK·FINDING을 통합하고 `현재 RUN / 전체 기록` 범위와 `RUN별 보기 / 레코드별 보기`를 독립적으로 선택합니다. 연상 기억은 기존처럼 작업 공간의 교훈·단서·출처를 읽기 전용으로 탐색합니다. |
| 좌측 하단 Management | 관리 제목 아래 `RUN 삭제`를 배치하며 기존 폐기 의미를 유지합니다. 기록이 있는 RUN은 이력으로 보관하고 빈 RUN은 삭제하는 절차를 안내하며, 정확한 RUN ID 확인 대화상자를 보여줍니다. 서버의 폐기 지원 여부와 RUN의 `writable`을 따르며 다른 로컬 세션도 쓰기 가능하면 선택할 수 있습니다. 읽기 전용 공유 이력에서는 비활성화합니다. 폐기는 외부 Agent·프로세스를 중지하지 않습니다. **시안의 확인 버튼은 실제 RUN이나 가상 데이터를 삭제하지 않습니다.** |

PC에서는 상단 바와 왼쪽 패널이 고정되고 오른쪽 본문만 스크롤합니다. 높이가 부족하면 왼쪽 패널 자체를 세로 스크롤하며 메모리·관리까지 접근할 수 있습니다. Explore 확장 목록은 별도로 스크롤합니다. 좁은 화면에서는 좌측 탐색을 메뉴로 열며 닫힌 패널은 키보드 탐색에서 제외합니다. RUN마다 페이지·검색 설정·선택 레코드가 분리되고, 다른 RUN의 검색 결과나 기억 출처를 선택하면 원문 RUN 탭으로 이동합니다. 아카이브 RUN은 기록 검색이나 연상 기억의 출처에서 열면 상단 맨 오른쪽에 임시 탭 하나로 표시합니다. 다른 RUN 탭을 선택하면 임시 탭은 사라지며, 이미 기본 탭에 있는 RUN은 중복하지 않습니다. 동일 RUN 내 페이지·언어·테마 전환에서는 유지하고, 돌아가기와 직접 링크에서는 선택한 RUN에 맞춰 표시합니다. 완료 여부와 아카이브 여부는 별개입니다. 같은 표시 ID라도 출처가 다른 RUN을 구분하는 예시가 포함됩니다.

탐색 확장 패널은 마우스를 옮길 수 있도록 닫힘을 잠시 유예하며 본문 배치를 밀지 않습니다. 키보드 Enter·Space·오른쪽/아래 방향키로 열고 목록에서 위·아래·Home·End로 이동합니다. Escape·왼쪽 방향키·닫기 버튼은 트리거로 복귀하며 Tab으로 패널을 벗어날 수 있습니다. 좁은 화면과 터치에서는 메뉴에서 클릭해 열고 화면 안에 겹쳐 표시하며 바깥 클릭으로 닫습니다. 상세에서 돌아오면 PC는 해당 탐색 트리거, 닫힌 모바일 메뉴는 메뉴 버튼으로 포커스를 복원합니다.

TASK 현황과 PLAN·TASK·FINDING 탭의 개수는 한국어 `12개`, 영어 `12 items`(단수 `1 item`)처럼 단위를 함께 표시합니다.

현재 RUN 상단에는 분류(`work_type`)·난이도·진행 방식(`workflow_mode`)·기록 방식(`record_mode`)과 각 설명을 표시합니다. 레이블·값을 한 줄로 압축하며 설명은 호버 도움말과 접근성 텍스트로 제공합니다. 좁은 화면에서는 정보 행만 좌우로 스크롤합니다. PLAN·작업 흐름의 섹션 제목, 카드 시작선·모서리·여백을 통일합니다. 진행 방식은 검토 엄격도를 뜻하며 난이도와 구분합니다. 난이도는 이 시안에 추가한 예시 정보로, 제품의 RUN 스키마를 변경하거나 연결하지 않습니다.

PLAN은 ID·상태·제목·짧은 목표와 원문 이동 화살표를 가진 요약 카드로 확인합니다. 한 줄에 배치하고 영역을 넘으면 수평 스크롤로 탐색합니다. 하나일 때는 영역의 폭을 채우고, 없으면 빈 상태를 표시합니다. 선택하면 Explore PLAN 원문으로 열고 돌아올 때 카드 포커스와 본문·가로 위치를 복원합니다. PLAN과 작업 흐름은 RUN별로 독립적인 가로 위치를 유지하며 언어·테마 전환과 폭 변경에도 복원합니다.

진행 단계와 단계별 본문 전환은 표시하지 않습니다. 기존 `phase` 링크도 현재 TASK 보드로 열립니다. TASK 영역은 막힘 안내와 수평 Flow 칸반으로 구성하며 별도의 진행 중인 작업 집중 카드는 표시하지 않습니다. 대기·진행 중·막힘·완료 열에는 단위를 붙인 개수와 TASK ID 순서의 제목·담당·선행 조건을 표시하며, 건너뜀 작업이 있으면 별도 열로 표시합니다. 카드는 읽기 전용이며 선택하면 Explore 상세로 열고 돌아갈 때 본문 스크롤과 원래 카드 포커스를 복원합니다. 모든 화면 폭에서 상태 열을 한 줄로 유지하며 칸반 안에서 좌우로 스크롤해 분류를 읽습니다. 내용이 남은 쪽의 경계는 투명도 그라디언트로 부드럽게 처리하며 시작·끝에서는 해당 쪽 페이드를 없앱니다. 세로 이동은 본문 스크롤을 사용합니다. 스크롤 영역은 키보드로 접근할 수 있고, RUN·언어·테마 전환과 돌아가기에서 가로 위치를 복원합니다. 캐러셀과 이어지는 작업·완료한 일 목록은 표시하지 않습니다.

상단 브랜드는 `tapl` 텍스트로 표시합니다. 내부 링크로 이동한 페이지에는 오른쪽 상단에 `돌아가기`가 나타납니다. TASK·검색 결과·연결 레코드·기억 출처에서 이동한 뒤 이전 RUN, 페이지, 검색·필터, 펼친 그룹, 선택 레코드와 스크롤 위치로 돌아갑니다. 언어·테마는 현재 설정을 유지합니다. 좌측 메뉴나 상단 RUN을 직접 선택하면 새 탐색을 시작하며 복귀 경로를 비웁니다. 직접 진입하거나 새로고침한 화면에는 복귀 버튼을 표시하지 않습니다.

기록 검색의 기본 범위는 전체 기록이며 현재 RUN으로 좁힐 수 있습니다. 검색 범위 선택에는 아래 화살표를 표시하고, RUN별·레코드별 보기 전환은 상태 필터와 같은 옅은 외곽선의 알약 형태로 구성합니다. RUN별 검색 결과는 제목·출처·일치 건수만 보이는 접힌 상태로 시작하며, 그룹을 펼쳐 개별 기록을 읽습니다. 검색 제출·범위 변경·검색 초기화 시 다시 접힙니다. 직접 펼친 상태는 언어·테마·보기 전환과 상세에서 돌아가기에 유지합니다. 레코드별 보기는 개별 기록을 바로 나열합니다.

한국어·영어 UI, 상태·안내·접근성 레이블과 예시 내용을 전환할 수 있으며 밝음·어두움도 지원합니다. 언어 전환은 실제 저장된 레코드의 자동 번역을 뜻하지 않습니다. 실제 제품의 locale 전달·기존 번역 키·사용자 작성 내용과 분리해 구현해야 합니다. 링크의 `#run=local24&page=tasks&lang=en&theme=dark`처럼 화면 문맥을 지정해 열 수도 있습니다.

화면에는 제목·상태·기록 내용·필요한 출처를 남기고 공통 소개, 데모 배지, 반복 푸터와 중복 문맥을 표시하지 않습니다. 선택한 RUN은 상단 탭에서 확인하며 현재 RUN·TASK 현황·Explore 상세의 본문 상단에는 RUN ID·세션·출처 행을 반복하지 않습니다. RUN별 검색은 그룹 헤더에 출처를 모으고 레코드별 보기에서는 각 결과에 표시합니다. 빈 상태 안내와 폐기 확인·영향 설명은 필요한 위치에 유지합니다.

밝은 테마는 차가운 회색·흰색 표면과 짙은 청록색 강조를, 어두운 테마는 남색 표면과 옅은 청록색 강조를 사용합니다. 본문·보조 글자와 행간을 키우고 얇은 구분선·절제된 그림자로 계층을 구분합니다. RUN 선택선과 본문은 260ms, 탐색 확장 패널은 160ms, 검색 그룹은 180–240ms로 전환하며 빠른 연속 조작은 진행 중 모션을 정리합니다. `prefers-reduced-motion`에서는 모션을 생략하고, 테마 색상은 즉시 교체합니다.

통합안은 제품 연결 전의 독립적인 가상 시안입니다. 기존 CLI·MCP·설정·VS Code 호스트·RUN 폐기는 변경하지 않습니다. 아래의 10종은 개별 정보 구조를 비교하는 대안으로 유지합니다.

통합안은 임시 프로필의 헤드리스 Chrome에서 한국어·영어, 밝음·어두움, 폭 320·390·1024·1600px의 RUN 정보·PLAN 요약과 주요 페이지를 확인했습니다. 직접 링크·PLAN/TASK/FINDING 원문 복귀·포커스·독립 가로 위치·본문 스크롤·RUN별 상태·읽기 전용·빈 상태와 일반/동작 줄이기를 검증했습니다. 수평 칸반의 휠·키보드·페이드 경계와 폭 변경 복원도 확인했습니다. 탐색 패널의 호버 연결·혼합 입력·키보드·터치·화면 크기 전환과 낮은 화면에서 왼쪽 패널·목록 스크롤을 확인했습니다. 기본 팔레트의 본문·보조 글자와 주요 버튼 22개 색상 조합은 최소 대비 4.64:1이었습니다. 대표 화면을 육안 검토했습니다. 실제 VS Code 호스트·고대비·스크린리더 검증을 대신하지 않습니다.

## 시안 살펴보기

[시안 10종 갤러리](../design/viewer-concepts/index.html)를 브라우저에서 여세요. 설치 없이 동작하며 스타일과 스크립트는 모두 로컬 파일입니다. GitHub의 HTML 원문에서는 미리보기가 실행되지 않으므로 저장소를 내려받아 열어야 합니다.

[전체 비교 이미지](../design/viewer-concepts/overview.png)도 볼 수 있습니다. 갤러리의 `#overview`는 전체 비교 화면으로 바로 연결됩니다.

- 왼쪽 목록 또는 이전·다음 버튼으로 시안을 바꿉니다. `#01`부터 `#10`까지 직접 접근할 수 있습니다.
- `함께 보기`, `Viewer`, `확장`과 밝음·어두움 테마를 비교합니다.
- `화면 상태`에서 정상·로딩·비어 있음·연결 오류를 확인합니다.
- 작업 상세, 상태 필터, 기록 검색, 기억 출처와 문서 탐색은 시안 안에서만 동작합니다. 검색 입력은 Enter로 제출합니다.
- `전체 시안 비교`에서 열 가지 정보 구조를 한눈에 비교합니다.

RUN·작업·담당·기록·시각은 모두 가상 예시입니다. 진행률 2/6도 비교용 데이터이며 실제 업그레이드 완료를 뜻하지 않습니다. 이 갤러리는 **DaisyUI 5.7.50 / Tailwind CSS 4.3.5**를 별도로 빌드합니다. 제품의 패키지 버전·설정·CLI·MCP 인자와 실행·승인·폐기 동작은 바꾸지 않습니다. 확장 미리보기는 좁은 webview 콘텐츠이며 VS Code의 네이티브 Tree View·호스트·CSP 실행을 재현하지 않습니다.

## 현재 구현에서 확인한 개선 지점

| 경계 | 현재 구현 |
| --- | --- |
| 공유 구조 | `workbench/Workbench.tsx`의 고정 PC 구조와 반응형 서랍 |
| 이동 | `model.ts`·`useWorkbench.ts`의 원본 포함 RUN 식별, 돌아가기와 RUN별 설정 |
| 페이지 | `RunViews.tsx`·`RecordsView.tsx`·`Explore.tsx`, `RecordDetail.tsx`·`MemoryView.tsx`·`SecondaryViews.tsx`의 읽기·보조 화면 |
| 테마 | 기존 TAPL·VS Code 색상에 연결한 DaisyUI 의미 토큰과 수동 라이트/다크 선택 |
| 호스트 | 정확한 RUN·기록 목록 계약을 공유하는 브라우저 HTTP·VS Code stdio 어댑터 |

동작 기준은 [Viewer 안내](../guides/viewer.ko.md)이며 갤러리 fixture는 실제 데이터가 아닙니다.

현재 RUN은 독립 시안의 배치·포인터 반응을 실제 데이터에 연결한 마인드맵만 표시합니다. 실제 PLAN 참조와 전체 TASK 상태를 사용하고, 부모가 없는 TASK는 RUN에 직접 연결합니다. `mindmap.ts`의 출처별 그래프와 `mindmapCamera.ts`의 뷰포트 제한을 `RunMindmap.tsx`에서 렌더링합니다. 축소 내비게이션은 같은 아이콘·레이블·숫자 DOM을 유지하며 폭·위치·투명도를 전환합니다. 동작과 입력·접근성은 [Viewer 가이드](../guides/viewer.ko.md#viewer-탐색)를 기준으로 합니다.

실제 상세는 시안의 hero·읽기 본문·속성 패널·실제 연결 기록 행을 따릅니다. 의미 있는 구조화 필드는 본문으로 올리고 추가 값은 수직 객체·배열 트리로 표시합니다. 기억은 문구 카드·원본 미리보기를 사용합니다. 워크스페이스는 모달이며 진단·오류·로딩도 같은 시각 체계를 따릅니다. 아이콘 툴팁과 상태 토큰을 페이지 전체에 공유하며 시안의 가상 검증 항목·관계·메타데이터를 실제 사실처럼 복사하지 않습니다.

PLAN 상세는 별도 내용 섹션 없이 의미별 항목을 읽도록 구성합니다. 형식이 다른 생성 Markdown을 가진 이전 기록을 포함해 원래 PLAN 본문은 접힌 추가 필드에서 확인합니다.

## 열 가지 방향

| 시안 | 핵심 정보 구조 | 확장 적용 | 적합한 용도·한계 |
| --- | --- | --- | --- |
| **01 Signal Desk** | 작업 목록 + 선택한 작업 상세 | 간결한 목록 + 상세 대화상자 | **통합안의 TASK 현황 기반.** 목록과 근거의 균형이 좋습니다. |
| **02 Flow Board** | 대기·진행·막힘·완료 레인 | 상태 필터 + 세로 레인 | **통합안의 현재 RUN 하단 작업 흐름 기반.** 작업이 많으면 본문이 길어집니다. |
| **03 Focus Now** | 현재 작업 + 목적·검증 + 다음 대기열 | 현재 작업을 첫 화면에 집중 | 현재 작업에 집중하는 대안입니다. 전체 비교에는 별도 목록이 필요합니다. |
| 04 Evidence Stream | 시간순 이벤트 + 근거 기록 | 세로 타임라인 | 재개·회고. 시각·순서를 의존성과 혼동하지 않아야 합니다. |
| 05 Record Library | 검색 결과 + 원문 | 결과 다음에 원문 배치 | 기록·아카이브 검색. 실시간 상태에는 덜 적합합니다. |
| 06 Memory Garden | 교훈 + 검색 단서 + 출처 | 한 열의 기억 카드 | 기억 전용 화면. 긴 내용은 점진적으로 펼칩니다. |
| 07 Run Atlas | 소유자·출처가 드러나는 RUN 카드 | RUN 카드 세로 목록 | 다중 세션·공유 이력. 단일 RUN에는 과할 수 있습니다. |
| 08 Spec Explorer | PLAN 아래 TASK·FINDING 탐색 | 탐색 뒤에 문서 배치 | 긴 계획·검증 기록. 깊은 계층은 접어야 합니다. |
| 09 Dependency Lens | 선행 TASK와 후속 TASK의 연결 | 위에서 아래로 조건 읽기 | 막힘 원인 분석. 그래프 배치는 별도 구현이 필요합니다. |
| 10 Quiet Outline | 짧은 개요 + 작업 목록 + 접힌 기록 | 단일 열의 점진적 공개 | 읽기·키보드 중심. 병렬 비교에는 보조 보기가 필요합니다. |

통합안은 **02 기반 현재 RUN과 01 기반 TASK 현황을 Workspace의 두 페이지로 묶고**, 검색에는 05, 기억에는 06, 레코드 탐색에는 08의 정보 구조를 적용합니다. 열 가지 화면 전체를 제품의 보기 옵션으로 추가하지 않습니다. 09의 의존성 보기는 후속 선택 사항입니다.

## DaisyUI 컴포넌트 활용

| 책임 | 컴포넌트 | 조합 원칙 |
| --- | --- | --- |
| 작업 공간·RUN 탐색 | `menu`, `dropdown`, `tabs` | 위치·출처를 항상 식별하고 탭 선택·방향키 동작을 보존합니다. |
| TASK 요약·목록 | `table`, v5 `list` / `list-row`, `card` | 넓은 화면은 표, 좁은 화면은 목록을 사용합니다. 모든 행을 카드로 만들지 않습니다. |
| 상태·진척 | `badge`, v5 `status`, `progress`, `steps` | 색과 텍스트를 함께 사용합니다. Skipped 등 실제 상태를 표시하고 TASK 완료 비율을 성공 판정으로 해석하지 않습니다. |
| 검색·필터 | `input`, `select`, `join`, v5 `fieldset` | 입력 레이블과 선택 상태를 명시합니다. 핵심 기능을 tooltip에만 두지 않습니다. |
| 상세·긴 기록 | `collapse`, `modal`, `tabs` | 원문·추가 필드를 필요할 때 펼치고 포커스 복귀·Escape를 지원합니다. |
| 이벤트·피드백 | `timeline`, `alert`, `skeleton`, `loading` | 새 데이터, 로딩, 빈 상태, 오류와 오래된 데이터를 구분합니다. |

기본 컴포넌트를 더 많이 넣는 것이 목표는 아닙니다. [공식 컴포넌트](https://daisyui.com/components/)의 구조·상태·크기를 사용하고, 제품 고유 CSS는 배치·밀도·토큰 연결에 집중합니다. 의존성 그래프는 DaisyUI 기본 기능으로 제공되지 않으므로 별도 배치·키보드 탐색 책임을 둡니다.

## 단계별 리팩토링 계획


### 1. 회귀 기준과 버전 전환

제품은 `pnpm-lock.yaml`에 DaisyUI **5.7.50**, Tailwind CSS·`@tailwindcss/vite` **4.3.5**를 고정합니다. React **18.3.1**·Vite **5.4.20**·VS Code 최소 **1.90**은 유지합니다. `styles.css`는 `@import "tailwindcss"`·`@plugin "daisyui"`를 사용하며 예전 JavaScript Tailwind/PostCSS 설정은 제거했습니다. Vite 빌드와 브라우저 자산 동기화는 `compile`로 실행합니다.

의미 색상 어댑터는 VS Code 변수·브라우저 기본값·수동 테마를 유지합니다. 상위 CSS 최적화기가 생략하는 join 선택자는 명시적인 포커스·호버 대체 규칙으로 보완합니다. [DaisyUI 업그레이드](https://daisyui.com/docs/upgrade/)와 [Tailwind 업그레이드](https://tailwindcss.com/docs/upgrade-guide)를 참고하세요.

### 2. 공유 UI의 책임 분리

Workbench 모듈이 이동과 페이지 조합을 맡습니다. 기존 기록 내용·사용자 필드·실행 상세·기억 화면·워크스페이스 선택·진단·정확한 ID 삭제 확인창은 공유합니다. 호스트 어댑터는 origin/CSP·원본 식별·읽기 전용·늦은 결과 방어를 유지합니다. 구버전 호스트가 RUN 문맥을 제공하지 않아도 현재 기록을 지어내지 않습니다. 새 기록 목록을 사용하려면 MCP 서버도 업데이트합니다.

### 3. 선택한 UX 적용

고정 RUN 탭·패널, 실제 존재하는 메타데이터 한 줄, 수평 PLAN·작업 흐름, 전체 TASK 목록과 단일 호버/클릭 탐색 패널을 적용했습니다. TASK 선택은 상세 페이지로 이동합니다. 기록 검색은 전체 기록·접힌 그룹이 기본입니다. 아카이브 원본은 임시 탭 하나로 표시하며 돌아가기는 원본 문맥·필터·스크롤·포커스를 복원합니다. [Viewer 탐색](../guides/viewer.ko.md#viewer-탐색)을 참고하세요.

### 4. 검증 후 적용

공유 webview TypeScript·호스트 계약·실제 Chrome 동작·Python 읽기 전용/원본 검사·패키지 자산은 [기여와 검증](contributing.ko.md)을 따릅니다. 환경이 준비되면 실제 VS Code·고대비·스크린리더를 별도로 검사합니다. 브라우저와 모의 호스트 검사만으로 이를 검증했다고 볼 수 없습니다. 아래 갤러리 검증은 합성 예제에만 적용됩니다.

## 갤러리 유지보수

저장소 루트에서 실행합니다. 생성된 `components.css`가 포함되어 있어 열람 시 설치가 필요 없습니다. 통합안도 이 로컬 CSS를 공유하며 `build`와 `check`가 두 시안을 함께 다룹니다.

```sh
npm --prefix docs/design/viewer-concepts ci
npm --prefix docs/design/viewer-concepts run build
npm --prefix docs/design/viewer-concepts run check
python3 -m http.server 8767 --bind 127.0.0.1 --directory .
```

서버를 사용하면 `http://127.0.0.1:8767/docs/design/viewer-concepts/`에서 엽니다. `index.html`을 직접 여는 방법도 지원합니다. `components.source.css`·`concepts.js`·`lab.css`가 편집 원본입니다. 화면 내용은 한국어이며 영문·국문 가이드는 같은 갤러리를 가리킵니다.

통합안은 `http://127.0.0.1:8767/docs/design/viewer-workbench/`에서 열며 `viewer-workbench/index.html`·`workbench.js`·`workbench.css`가 편집 원본입니다. 한국어·영어는 시안 상단에서 전환합니다.

현재 고정 버전의 minify 빌드는 DaisyUI `join`의 `@scope` 내부 선택자에 대해 최적화 경고 2건을 출력합니다. 생성은 성공하며 갤러리에는 별도의 명시적 focus 경계가 있습니다. 제품 업그레이드에서는 이 경고와 지원 최저 webview의 선택자·포커스 렌더링을 다시 확인해야 합니다.

갤러리는 임시 프로필의 헤드리스 Chrome에서 320·390·640·1024·1600px × 10종 × 밝음·어두움 × 3개 표면 조합 300개, 추가 상태 30개를 확인했습니다. 이 범위에서 페이지·제품 영역의 가로 넘침, 스크립트 오류와 외부 요청은 없었고 필터·검색·상세·문서 선택·포커스 복귀를 확인했습니다. 대표 화면은 육안으로도 검토했습니다. 실제 VS Code webview·고대비·스크린리더·사용성 검증을 대신하지 않습니다.
