# 로컬 식별자와 공유 이력

[문서 홈](../README.ko.md) · [English](storage.md)

TAPL은 정확한 작업 폴더의 `.tapl/tapl-{UUID}.db`에 각 로컬 환경의 기록을 저장합니다. 이력 검색·아카이브·메모리 회상·Viewer는 같은 폴더의 다른 `tapl-*.db`도 읽습니다. 워크플로 변경은 로컬 DB에만 기록합니다.

## 영속 설치 식별자

기본 쓰기 DB가 처음 필요한 작업에서 임의의 UUID v4를 `~/.tapl/installation_id`에 생성합니다. 동시에 시작해도 하나의 완성된 값을 재사용합니다. 같은 로컬 사용자 환경의 모든 워크스페이스는 같은 UUID 접미사를 사용하며, 기록 자체는 각 워크스페이스에 남습니다. 이 식별자는 Codex 계정·세션·설치 ID와 독립적입니다.

식별자 파일은 `config.toml`과 분리되어 있습니다. `--purge-config`와 `--purge-db`를 포함한 TAPL 제거에서도 보존합니다. 따라서 재설치하면 같은 DB 이름을 선택합니다. 실행 파일만 제거할 때도 이 파일은 남습니다.

UUID는 로컬 사용자의 홈 디렉터리를 따릅니다. 홈을 다른 환경에 복사하면 식별자도 복사됩니다. 식별자가 잘못됐으면 임의로 재발급하지 않고 오류를 표시합니다. 백업이나 본인의 로컬 DB 파일명에서 원래의 정규 UUID v4를 복원하세요. 읽기 전용 Viewer 탐색은 식별자를 생성하지 않습니다.

## 기존 DB 이전

업그레이드 전에 기존 TAPL MCP 서버·hook과 다른 DB 사용 프로세스를 종료하세요. 다음 기본 쓰기 초기화에서 `.tapl/tapl.db`를 `.tapl/tapl-{UUID}.db`로 이전합니다. 예를 들면 다음과 같습니다.

```sh
taplctl init --workspace-root /path/to/workspace
```

TAPL은 기존 DB를 확인하고 커밋된 WAL 데이터를 반영한 뒤, 독점 접근을 확보하고 SQLite 연결을 닫아 목적 파일을 덮어쓰지 않고 이동합니다. 파일명 이전에 성공하면 기존 `tapl.db` 이름은 없어집니다. DB를 병합하거나 파일명 이전 전용 백업을 별도로 생성하지는 않습니다. 기존 스키마 업그레이드의 버전별 백업 동작은 유지합니다.

사용 중인 DB, 지원하지 않거나 잘못된 원본, 기존 목적 파일 또는 목적 파일의 보조 파일이 있으면 이전을 중단하고 원본을 보존합니다. 표시된 원인을 해결한 뒤 다시 실행하세요. 이전이 중단된 뒤에는 `.tapl/.legacy-migration.lock`을 제거하기 전에 두 파일명을 확인해야 합니다. 실행 중인 프로세스의 잠금은 제거하지 마세요. 파일명 이전을 되돌리려면 모든 TAPL 프로세스를 종료한 뒤 완전한 DB를 이전 이름으로 이동합니다. 스키마 백업을 복원하기 전에는 이후 기록을 별도로 보존하세요.

읽기 전용 Viewer는 이전 전의 기존 DB도 살펴볼 수 있지만 직접 이전하지 않습니다. 이전하면 원본 파일명이 바뀌므로 Viewer를 새로 고치세요. 관리 명령의 명시적 `--db PATH`는 계속 그 파일을 선택합니다.

## 여러 DB 조회

선택한 작업 폴더만 탐색하며 부모 폴더나 Git 루트는 찾지 않습니다. 같은 폴더의 `.tapl`에 다른 환경의 `tapl-*.db`를 두면 이력을 참조할 수 있습니다. symlink DB와 디렉터리는 따라가지 않습니다.

검색·아카이브 목록·메모리 회상은 읽을 수 있는 원본을 합칩니다. 결과에는 정확한 DB 파일명인 `source_db`가 포함됩니다. 항목·아카이브·메모리·RUN 상세를 요청할 때 이 값을 전달하세요. DB마다 항목 번호와 아카이브 slug가 같을 수 있으므로 ID만으로 다른 환경의 기록을 구분할 수 없습니다. `source_db`를 생략하면 로컬 이력을 선택합니다.

```json
{"session_id":"<current-hook-session-id>","item_id":42,"source_db":"tapl-123e4567-e89b-42d3-a456-426614174000.db","compact":true}
```

위 예시는 `tapl_get_item` 인자이며 실제 검색 결과의 파일명을 사용해야 합니다. Viewer는 상세 열기와 새로 고침에서 원본 선택을 유지합니다. 다른 환경의 RUN도 보여주지만 확인을 통한 폐기는 로컬 RUN만 지원합니다.

검색은 서로 다른 인덱스의 원점수를 직접 비교하지 않고 DB별 순위를 합친 뒤 전체 결과 제한을 적용합니다. 아카이브와 수동 메모리 페이지 제한도 통합 결과에 적용합니다. 읽을 수 없거나 손상됐거나 호환되지 않는 원본은 `source_errors`에 표시하고 정상 원본은 계속 조회합니다. 읽는 동안 다른 환경의 DB를 마이그레이션하지 않으며 소유자가 업데이트해야 합니다. 자동 회상은 기존 바이트 제한을 유지하며 생략한 원본 오류 수를 `source_errors_omitted`로 요약할 수 있습니다.

다른 환경 메모리의 변경·삭제는 거절합니다. 완료 시 `memory_uses`에도 `source_db`를 포함하세요. 다른 환경의 사용 기록은 읽기 전용 skip으로 보고하며 해당 DB의 기억을 강화하지 않습니다. 다른 DB에 같은 메모리 ID가 있어 원본 생략이 모호하면 원본을 전달할 때까지 사용 기록을 거절합니다. [메모리](memory.ko.md)와 [MCP 참조](../reference/mcp.ko.md)를 참고하세요.

## 제거와 공유 범위

`--purge-db`는 선택한 범위의 로컬 UUID DB, 기존 DB와 해당 SQLite 보조 파일을 제거합니다. 다른 환경의 DB·백업·`~/.tapl/installation_id`는 보존합니다. `--purge-config`는 설정만 제거합니다. [CLI 제거 옵션](../reference/cli.ko.md#uninstall)을 참고하세요.

탐색은 로컬 파일 접근이며 Git clone 간 동기화 기능은 아닙니다. 이 저장소는 기본적으로 워크플로 DB를 Git에서 제외합니다. 이력을 전달하려면 쓰기 프로세스를 종료하거나 일관된 SQLite 백업을 만든 뒤 복사하세요. 커밋된 기록이 WAL에 남아 있는 실행 중 DB의 본 파일만 복사하지 마세요. 같은 식별자를 여러 독립 clone에서 사용하면 같은 DB 파일명을 수정할 수 있으므로 파일 탐색이 바이너리 병합 충돌을 해결하지는 않습니다.
