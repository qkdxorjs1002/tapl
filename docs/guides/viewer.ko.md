# Viewer와 서비스

[문서 홈](../README.ko.md) · [English](viewer.md)

브라우저 Viewer는 로컬 TAPL 워크스페이스의 활성 RUN, 계획, 작업, 승인, 발견 사항, 아카이브, 이력 검색, 연상 메모리를 보여 줍니다. 메모리 목록·검색·상세·원본 확인은 읽기 전용입니다. 메모리 수정이나 삭제는 에이전트에게 명시적으로 요청하세요.

같은 Viewer에서 Codex와 Claude Code RUN을 읽습니다. 소유 세션을 명시적으로 선택하며 Claude 소유자에는 `claude-code:` 접두사가 있습니다. [Claude Code](../getting-started/claude-code.ko.md)를 참고하세요.

Viewer는 같은 폴더의 `tapl-*.db`를 함께 조회하고 상세·새로 고침에서 원본 DB를 유지합니다. 다른 환경의 RUN은 조회만 가능하며 폐기할 수 없습니다. 읽기 전용 탐색은 UUID도 생성하지 않습니다. [로컬 식별자와 공유 이력](storage.ko.md)을 참고하세요.

## 워크스페이스 열기

초기화한 작업 폴더에서 실행합니다.

```sh
taplctl viewer
# tapl viewer: http://127.0.0.1:8000

# 필요하면 다른 포트 사용:
taplctl viewer --port 9000
```

출력된 URL을 직접 여세요. 명령은 브라우저를 자동 실행하지 않으며 `Ctrl+C`로 종료합니다. CLI는 `127.0.0.1`에만 바인딩합니다. 시작 폴더의 `.tapl/tapl-{UUID}.db`를 선택하며 부모 폴더를 검색하지 않습니다. 하위 폴더를 별도로 초기화하면 별도 워크스페이스입니다.

시작 폴더에 DB가 없으면 페이지에서 `.tapl/tapl-{UUID}.db`가 있는 폴더를 선택합니다. 브라우저는 마지막으로 성공한 선택을 기억합니다. 로그인 서비스가 저장소 밖에서 시작될 때 유용합니다. 폴더 선택은 초기화 작업이 아니므로 먼저 `taplctl init --workspace-root /path/to/workspace`를 실행하세요. Viewer에는 `--workspace` 옵션이 없습니다.

워크스페이스 선택 창에는 숨김 폴더를 포함한 하위 폴더 목록이 표시됩니다. 폴더를 누르면 안으로 들어가고, 목록 맨 위의 **../** 항목으로 상위 폴더에, **홈** 버튼으로 홈 폴더에 이동한 뒤 현재 폴더에서 **워크스페이스 열기**를 누릅니다. 선택된 워크스페이스에서 시작하며, 아직 선택하지 않았다면 서버의 시작 폴더에서 탐색합니다. 프록시로 페이지를 열어도 경로는 Viewer 서버가 실행되는 컴퓨터를 기준으로 합니다. 경로 입력란과 **폴더로 이동**도 빠른 이동용으로 사용할 수 있습니다. 탐색은 폴더를 생성하거나 초기화하지 않으며, TAPL DB가 없는 폴더는 워크스페이스로 열 수 없습니다. 접근 권한이나 폴더 삭제로 오류가 나도 현재 워크스페이스는 유지되므로 상위 폴더로 돌아가거나 다른 경로를 선택하세요. 폴더 목록 요청에는 설정 요청과 마찬가지로 허용된 HTTP `Origin`이 필요합니다.

RUN 탭에서 살펴볼 세션을 선택합니다. 아카이브와 이력 검색으로 이전 작업을 찾고, 메모리 화면에서 재사용 단서의 원본 근거로 이동할 수 있습니다. RUN을 선택해도 소유권은 바뀌지 않습니다.

## Viewer 탐색

돌아갈 화면이 있으면 **돌아가기** 버튼이 본문 오른쪽 위에 떠 있으며, 설정이나 기록 상세를 스크롤해도 같은 위치를 유지합니다. 기존 페이지 이력을 따라 돌아가며 키보드로도 실행할 수 있습니다.

RUN 바는 고정됩니다. PC 탐색은 아이콘 레일로 시작하고 호버나 키보드 포커스로 레이블을 페이지 위에 펼칩니다. 패널을 벗어나면 0.6초 뒤 축소하며 다시 들어오면 취소합니다. 고정하지 않은 패널은 유예 중에도 외부를 클릭하면 즉시 축소하고, 패널·탐색 확장 목록 안의 클릭은 외부로 처리하지 않습니다. 테마 아이콘 다음 맨 오른쪽의 고정 버튼을 누르면 펼친 상태로 유지하고 본문 폭에 반영하며, 고정 설정은 RUN별 설정과 별도로 기억합니다. 축소 레일에는 숫자 배지 없이 아이콘만 표시합니다. 펼친 탐색에는 단위가 붙은 전체 수량을 표시하고 툴팁과 접근성 이름도 전체 수를 유지합니다. 현재 RUN의 캔버스는 페이지 스크롤 대신 위치를 이동합니다. 화면 높이가 낮으면 패널도 따로 스크롤하며, 좁은 화면에서는 탐색 서랍을 사용합니다. 웹 Viewer에서는 작업 공간 제목 오른쪽의 폴더 아이콘으로 폴더 선택 모달을 엽니다. 취소·잘못된 경로·같은 폴더 선택은 현재 RUN·페이지·필터·스크롤을 유지하며, 검증을 통과한 다른 폴더로 바꿀 때만 워크스페이스 탐색 문맥을 초기화합니다. 문자 브랜드 옆에는 테마·패널 고정 아이콘이 있습니다. UI 언어는 관리 → 설정에서 선택하며 저장된 기록의 언어는 유지됩니다. 확장은 처음에 VS Code 테마 색상을 따르며 직접 선택한 테마를 유지합니다.

마인드맵은 페이지가 숨겨지거나 포커스를 잃으면 모션을 멈추고 돌아오면 재개합니다. 시간 값만 갱신되면 기존 배치를 유지하며 제목·상태·연결 관계의 변경은 계속 반영합니다. 노드를 열면 최신 기록 내용을 사용합니다.

- **현재 RUN**은 중앙 RUN → PLAN → TASK 흐름과 Agent의 메모리·히스토리 참조를 표시합니다. 모든 TASK 상태를 포함하며 실제 상위 PLAN이 없는 TASK는 RUN에 직접 연결합니다. RUN의 정수 완료율과 PLAN별 완료/전체 수를 표시하고, PLAN·TASK 노드는 원본 상세를 엽니다.

  메모리·기록 카드는 테마를 따르는 보라·주황 계열로 구분합니다. 조회만 하고 원문을 열지 않은 항목에는 선이 없고 원문을 열면 정확한 출처 관계만 연결합니다. 메모리의 포인터와 열린 원문이 일치할 때만 둘을 연결합니다. 연결선은 노드 상대 위치에 따라 좌·우·위·아래 변을 선택한 뒤 해당 변의 중앙 35% 구간(변 길이의 32.5%~67.5%) 안에서만 움직입니다. RUN 아래의 참조 가지에도 같은 범위를 적용합니다. 참조는 TASK 진행률과 실행 경로 애니메이션에 영향을 주지 않습니다. 메모리·기록 개수 버튼은 해당 카드로 이동하고 자동 추적을 끕니다. 카드를 열면 기존 상세로 이동하며 돌아가기로 원래 RUN에 복귀합니다. 기록 범위는 [Agent 조회 기록](memory.ko.md#agent-조회-기록)을 참고하세요.

  활성 RUN은 자동 추적 ON으로 시작합니다. **RUN과 진행 중인 작업 추적** 버튼으로 ON/OFF를 전환합니다. **진행 중(In Progress)** TASK·실제 상위 PLAN·RUN이 함께 보이도록 중심과 확대율을 맞춥니다. 동시에 진행하는 작업을 함께 표시하고 과도하게 확대되지 않도록 제한합니다. 진행 중 TASK가 없으면 **진행 중** PLAN을 따라가며, 둘 다 없으면 RUN만 추적합니다. 참조 카드는 자동 추적 범위를 늘리지 않습니다. 켜는 즉시 중앙에 맞추고 기록 갱신이나 화면 크기 변경에 따라 대상을 다시 맞춥니다. 노드를 호버하거나 클릭해도 추적을 유지합니다.

  드래그·두 손가락 또는 휠 이동·핀치 확대·축소에는 화면이 부드럽게 휘어지듯 따라오고, 긴 탄성 구간에서 점점 저항이 커집니다. 중간에 놓으면 추적 대상으로 부드럽게 복귀하며, 복귀 중 새 제스처는 현재 보이는 위치에서 이어집니다. 핀치 중 한 손가락만 남아 있어도 현재 뷰를 유지합니다. 충분히 멀리 당기면 추적이 OFF로 바뀌어 화면이 튀지 않고 자유 조작으로 이어집니다. 해제는 이동 거리나 배율로 결정하며 일정 시간 유지할 필요는 없습니다. 연속 제스처는 이동량을 누적하지만 떨어진 작은 제스처는 새로 시작하므로 사소한 트랙패드 움직임으로 추적이 꺼지지 않습니다. 도구 모음 확대·축소와 키보드 카메라 조작은 즉시 추적을 끄며 추적 버튼으로 재개합니다. 같은 페이지 세션에서 상세 왕복·RUN 전환 시 원본 DB와 RUN별 카메라·ON/OFF 선택을 기억합니다. 페이지를 새로 로드하면 활성 RUN은 다시 ON으로 시작하며, 종료 RUN에는 추적 버튼이 없습니다.

  복귀할 때는 작은 탄성 반동 후 안착합니다. 같은 RUN의 실시간 갱신은 진행 중인 제스처와 복귀 모션을 유지하며, 제스처가 끝나면 최신 RUN·PLAN·TASK 위치를 따라갑니다.

  추적 중 두 손가락 이동은 가속된 입력을 보정하고 추가 카메라 보간 없이 반응합니다. 가속 보정 후 해제 거리 기준은 클릭 드래그와 같으므로 적당히 연속해서 밀면 추적이 OFF가 되고 그 위치를 유지합니다. 해제 전에는 손가락을 대고 있어도 입력이 멈추면 기존처럼 탄성 복귀합니다. 손을 뗀 뒤 남는 스크롤 관성은 화면을 더 늘리거나 추적을 해제하는 대신 탄성 복귀를 시작합니다. 새 제스처는 현재 보이는 위치에서 이어집니다. 브라우저의 [wheel 관성 신호](https://w3c.github.io/pointerevents/#interface-wheelevent)가 있으면 우선 사용하며, 없으면 연속 감속으로 추정하므로 기기에 따라 감각에 차이가 있을 수 있습니다.

  추적 ON에서는 진행 중인 TASK와 상위 경로가 호버한 것처럼 계속 강조됩니다. 진행 중 TASK가 없으면 진행 중 PLAN을, 둘 다 없으면 RUN을 강조하며, 대기 중인 형제 항목은 흐리게 유지합니다. 직접 호버하거나 키보드 초점을 옮기면 해당 항목이 우선하며 벗어나면 자동 강조로 돌아옵니다. 추적 OFF나 종료 RUN에서는 직접 호버·포커스만 강조합니다. 진행 중인 유리관과 흐르는 빛이 함께 강조되며 흐름을 처음부터 재시작하지 않습니다. 대기 경로는 움직이지 않습니다.

  드래그·두 손가락 스크롤은 양축 이동, 핀치·Ctrl+휠은 제스처 위치 기준 확대·축소, Shift+휠은 수평 이동입니다. 방향키와 +/−를 사용할 수 있고 Escape·중앙으로는 추적을 끄고 읽을 수 있는 크기로 RUN 중심에 복귀합니다. 이동·최소 확대율은 실제 노드 범위와 화면 크기로 제한해 멀리 벗어나지 않게 합니다. 클릭·드래그에는 캔버스 포커스 테두리가 나타나지 않으며 키보드 포커스는 보입니다. 포인터에 노드와 연결선이 함께 반응하며 모션은 기본 활성화이며 시스템 동작 줄이기 설정을 따릅니다.
- **설정**은 관리 아래에 있으며 CLI가 지원하는 모든 선호와 Viewer 언어를 편집합니다. 변경 사항을 저장하거나 확인 후 기본값으로 초기화합니다. 설정 대상 파일은 현재 작업공간을 따릅니다. [Viewer 설정](configuration.ko.md#viewer-설정)을 참고하세요.
- **TASK 현황**에서 전체 TASK를 필터링합니다. 선택한 TASK는 상세 페이지로 열리고 **돌아가기**는 이전 필터·검색어·스크롤·포커스를 복원합니다.
- **탐색**의 PLAN·TASK·FINDING에 호버하거나 클릭하면 오른쪽에 하나의 목록이 뜹니다. 목록은 독립적으로 스크롤합니다. 키보드에서는 Enter나 오른쪽 화살표로 열고 Escape로 닫습니다.
- **기록 검색**은 전체 기록과 접힌 RUN 그룹으로 시작합니다. 전체/선택한 RUN 범위와 RUN별/레코드별 보기를 바꿀 수 있습니다. [검색](search.ko.md#viewer에서-기록-둘러보기)을 참고하세요.
- **연상 기억**은 워크스페이스를 중심으로 현재 결과 페이지의 원문·기억·단서를 사방으로 연결합니다. 중심은 연결된 DB의 결과를 모으며 실제 출처 관계를 바꾸지 않습니다. 같은 출처나 정규화 후 같은 단서는 가지를 공유합니다. 기억은 상세, 원문은 원본 기록·RUN, 단서는 검색을 엽니다. 자동 추적 없이 직접 이동·핀치·키보드·동작 줄이기 조작을 유지하고, 돌아오면 워크스페이스·검색·페이지별 카메라를 복원합니다. 검색·페이지 이동·진단도 유지합니다. [연상 기억](memory.ko.md#viewer에서-기억-읽기)을 참고하세요. 관리 제목 옆에서 디버그를 실행합니다.

상단에는 아카이브하지 않은 RUN을 표시합니다. 기록이나 기억에서 아카이브 원본을 열면 오른쪽에 임시 탭 하나를 추가하고, 다른 RUN으로 이동하면 없앱니다. 원본 DB와 RUN ID를 함께 유지합니다. 내부 링크에는 돌아가기를 제공합니다. 이미 선택한 RUN 탭을 다시 누르면 현재 페이지와 복귀 이력을 유지하며, 다른 RUN·패널 메뉴로 직접 이동하거나 새로 로드하면 복귀 이력을 초기화합니다. RUN별 필터와 테마·언어 선택은 복귀 이력과 별도로 유지합니다.

페이지·RUN·원본·상세 변경에는 짧은 전환 효과를 사용하며 폴링이나 필터 편집에는 반복하지 않습니다. 메뉴와 대화상자도 부드럽게 열고 닫으며, 시스템 동작 줄이기를 켜면 애니메이션과 전환 대기를 없앱니다.

두 지도 모두 모든 노드를 키보드로 탐색할 수 있습니다. 포인터 모션은 가까운 노드와 연결선만 갱신합니다. 활성 RUN에서는 **진행 중(In Progress)** 항목과 그 상위 경로에만 유리관 같은 연결선 내부로 빛이 흐르고 주변에 여러 겹의 광채를 더하며, 다른 항목을 호버해도 흐름이 시작되지 않습니다. 다른 상태·종료 RUN·연상기억의 관계선에는 흐름이 없습니다. 이동하는 빛은 화면 내 실행 경로 중 최대 24개를 초당 30회 갱신합니다. 정지한 노드·연결선 형상은 재사용하며 지도가 숨겨지거나 시스템 동작 줄이기가 켜지면 장식 처리를 멈춥니다. 카메라 이동은 별도의 프레임 속도를 유지합니다.

반복 snapshot에서는 바뀌지 않은 지도 데이터와 뷰포트 형상을 재사용합니다. 기록 내용은 즉시 갱신하며 배치·연결·실행 상태가 달라지면 해당 뷰포트 캐시를 다시 구성합니다. 카메라가 움직일 때 이동하는 빛의 후보는 실행 중인 연결선에서만 확인합니다.

## 상세와 구조화된 필드 읽기

PLAN·TASK·FINDING 상세는 읽기 본문과 별도 속성 패널로 구성합니다. PLAN의 목적·요구사항·접근 방식·영향 범위·실행 순서·위험·검증·승인 필요 사항은 기록된 경우 표시합니다. PLAN에는 별도의 내용 섹션을 표시하지 않으며 원래 본문은 접힌 추가 필드에서 확인할 수 있습니다. TASK의 목표·작업·결과·검증·막힘 사유·다음 행동, FINDING의 발견 내용·영향도 본문에서 읽습니다. 관련 기록은 원본 RUN 안의 실제 참조로 연결하며, 구조화된 필드와 정확히 같은 TASK 생성 Markdown은 한 번만 표시합니다.

담당·시각·상태·원본 DB·상위 PLAN은 속성에 표시합니다. 추가·커스텀·실행 필드는 JSON 원문 덩어리 대신 수직으로 나열한 중첩 구조이며 객체·배열을 펼쳐 읽습니다. 0·false·null·빈 객체·빈 배열을 구분합니다. 기억과 진단의 필드도 같은 방식으로 표시합니다.

아이콘 전용 컨트롤에는 짧은 한·영 호버/포커스 툴팁을 제공합니다. 상태는 문구와 구분 표식을 유지하며 호스트의 의미 색상을 따릅니다. 기본 팔레트에서는 대기=슬레이트·진행 중=블루·막힘=테라코타·완료=그린·건너뜀=바이올렛으로 구분합니다. 진단의 훅 이벤트는 시간순으로 읽고 데이터 필드를 펼칠 수 있습니다. 로딩·오류·미지원 상태도 고정 화면 구조 안에 표시합니다.

VS Code 자동 테마에서는 상단·패널·두 지도·상태 표시·입력·모달·툴팁·읽기 영역이 현재 호스트 색상과 실시간 테마 변경을 따릅니다. 일반 경계는 호스트의 에디터·표면 보더 색상을 추가 투명도 없이 사용하며, 이전 테마는 사이드바·패널·에디터 그룹 보더로 대체합니다. 입력·팝업·툴팁은 각 역할의 보더 토큰을 사용합니다. 키보드 포커스와 고대비 경계는 분명하게 구분합니다. [VS Code 테마 색상 참조](https://code.visualstudio.com/api/references/theme-color)를 확인하세요. 직접 선택한 라이트/다크 팔레트가 우선합니다.

## DB 접근과 보호된 서비스

설정을 저장하려면 선택된 설정 파일과 디렉터리에 쓰기 권한도 필요합니다. DB 기록은 아래 읽기 전용 접근을 유지합니다.

Viewer 데이터 요청은 선택한 DB를 SQLite `mode=ro`와 `query_only`로 열고 연결마다 읽기 트랜잭션을 사용합니다. DB 생성, 저널 모드 변경, 스키마 마이그레이션, 메타데이터 갱신을 수행하지 않습니다. 서비스는 `~/.tapl/tapl-{UUID}.db` 없이 시작할 수 있으므로 시작 검사에서 해당 파일을 필수로 요구하지 마세요. 페이지나 `revision` 응답 성공은 웹서버 또는 파일 메타데이터 확인 결과이며 SQLite 조회 성공을 보장하지 않습니다.

DB는 설치된 TAPL의 스키마와 일치해야 합니다. 마이그레이션이 필요하면 보호된 Viewer 서비스 밖에서 DB 디렉터리에 쓰기 권한이 있는 사용자로 다음 명령을 실행한 뒤 새로고침하세요.

```sh
taplctl --db /path/to/history.db init
```

이 명령은 DB 옆에 마이그레이션 백업을 만들 수 있습니다. 지원 버전보다 새로운 스키마는 TAPL을 업그레이드해야 합니다. Viewer는 DB를 다운그레이드하지 않습니다.

systemd의 `ProtectSystem=strict` 또는 `ProtectHome=read-only`를 쓰면 서비스 사용자에게 워크스페이스의 읽기·디렉터리 탐색 권한이 필요합니다. SQLite WAL DB는 읽을 수 있는 기존 `tapl-{UUID}.db-wal`·`tapl-{UUID}.db-shm` 파일이 있거나 DB 디렉터리에 이를 생성할 권한도 필요합니다. 사용 가능한 보조 파일이 있으면 다른 프로세스가 쓰는 동안에도 DB 쓰기 잠금을 잡지 않고 WAL의 커밋된 변경을 조회합니다. 미커밋 변경은 보이지 않습니다.

모든 쓰기 연결이 닫히면 SQLite가 보조 파일을 제거할 수 있습니다. 따라서 보조 파일이 없는 WAL DB는 완전히 읽기 전용인 디렉터리에서 조회에 실패할 수 있습니다. 신뢰할 수 있는 쓰기 연결과 사용 가능한 보조 파일을 유지하거나, systemd의 `ReadWritePaths=/path/to/workspace/.tapl`로 선택한 `.tapl` 디렉터리만 쓰기를 허용하세요. 보조 파일을 수동 생성하거나 실행 중인 DB에 `immutable=1`을 적용하지 마세요. SQLite의 변경 감지를 우회해 WAL의 커밋된 내용을 놓칠 수 있습니다. [SQLite의 읽기 전용 WAL 조건](https://www.sqlite.org/wal.html#read_only_databases)을 참고하세요.

확인된 [RUN 폐기](#run-폐기)는 별도 쓰기 API를 사용하므로 디렉터리 쓰기 권한이 계속 필요합니다. 읽기 권한만 있는 서비스는 기록을 살펴볼 수 있지만 RUN을 폐기할 수 없습니다. 선택적 의미 검색은 모델 캐시도 필요할 수 있습니다. 제공자 설정과 BM25 대체 동작은 [검색](search.ko.md)을 보세요.

## RUN 폐기

RUN 탭을 선택한 뒤 왼쪽 패널의 **관리 → RUN 삭제**를 누르고 대화상자에 표시된 **전체 RUN ID**를 그대로 입력하거나 붙여 넣습니다. `PLAN-001`, 세션 ID, 축약 해시가 아닌 RUN 식별자입니다. 대소문자와 공백까지 일치해야 확인 버튼이 활성화됩니다. 취소하거나 Escape를 누르면 아무것도 바뀌지 않습니다.

확인 후 동작은 다음과 같습니다.

- 선택한 RUN과 같은 소유자·split group의 모든 대기 RUN을 의존성 연결 여부와 무관하게 함께 처리합니다.
- 각 RUN은 보존할 기록이 있으면 계획·작업·발견 사항과 함께 강제 아카이브하고, 정말 비어 있으면 아카이브 없이 삭제합니다. 결과, 실행 이력, 메모리, 보존 참조도 남겨야 할 기록으로 취급합니다.
- 활성 DB 실행과 배치를 취소하고 작업 타이머를 멈춥니다. 대기 RUN은 자동 시작하지 않습니다.
- 다른 세션과 무관한 요청은 유지합니다. 외부 에이전트 프로세스는 계속 실행됩니다. 폐기는 TAPL 상태만 바꿉니다.

브라우저 요청에는 허용된 `Origin`이 있어야 합니다. 서버는 선택한 워크스페이스, 소유 세션, 정확한 RUN ID, 명시적 확인도 검증합니다. 대응 도구 계약은 [MCP 참조](../reference/mcp.ko.md#confirmed-discard)를 보세요.

## Homebrew 서비스로 실행

설치한 formula를 시작합니다. 세 formula 모두 8000 포트를 사용하므로 해당 포트에서는 Viewer 서비스를 하나만 실행하세요.

```sh
brew services start taplctl
# 다른 선택: taplctl-semantic 또는 taplctl-pre
brew services restart taplctl
brew services stop taplctl
```

업그레이드·재설치는 실행 중인 Viewer 서비스의 재시작을 시도합니다. semantic formula는 검색 데몬을 미리 올리지 않습니다. Unix에서 필요할 때 따로 시작하세요.

```sh
taplctl searchd start
taplctl searchd status
```

`searchd`는 Unix 소켓을 사용하므로 Windows에서 지원하지 않습니다. Windows는 선택 의존성을 설치하면 데몬 없이 로컬 의미 검색을 사용할 수 있으며 BM25/전문 검색도 유지됩니다. [검색](search.ko.md)을 참고하세요.

## 역방향 프록시와 터널

신뢰할 수 있는 프록시나 터널로 다른 브라우저 origin에서 Viewer를 제공하면 정확한 origin을 허용합니다.

```sh
taplctl viewer --allowed-origin https://tapl.example.com
```

지속 실행하는 Homebrew 서비스는 적용되는 설정에 다음을 넣고 해당 formula를 재시작합니다.

```toml
[viewer]
allowed_origins = [
  "https://tapl.example.com",
  "https://tapl.internal.example",
]
```

```sh
brew services restart taplctl
```

origin에는 HTTP(S) 스킴, 호스트, 선택적 포트만 넣습니다. 경로·사용자 정보·쿼리·프래그먼트·와일드카드는 허용하지 않습니다. 여러 값은 `--allowed-origin`을 반복합니다. CLI와 설정의 origin은 로컬 origin과 합쳐집니다. 이 설정은 해당 브라우저 origin의 요청을 허용하며 일반 CORS를 켜거나 loopback 바인딩을 바꾸지 않습니다. 로컬 워크플로 데이터에 외부 접근을 제공하기 전에 프록시에서 인증과 TLS를 처리해야 합니다.
