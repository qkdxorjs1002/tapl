2026-09-28 TAPL 추가 컨텍스트·왕복 개선

기준은 `ef40aaf`, 작업 브랜치는 `perf/context-roundtrip-regression`이다. 행동·기능, 컨텍스트, 속도 순서로 평가한다. 구현과 자동 회귀는 완료했으며, **실제 Codex 대화 반복은 인증 정보 전송 승인 대기 상태**다. 현재까지 새 실제 대화 실행은 0회다. 이번 변경의 실제 누적 입력 토큰·최대 단일 입력·대화 속도 개선은 아직 주장하지 않는다.

자동 승인 검토가 호스트 Codex 로그인 정보를 네트워크가 활성화된 테스트 Box에 복사하는 작업을 거절했다. 기존 테스트 지시만으로 자격 증명 전송이 명시적으로 승인됐다고 볼 수 없다는 사유다. 테스트 전용 사용 후 인증 파일과 Box를 삭제하는 조건으로 승인을 요청했으며, 우회하지 않았다.

제품 변경

- `tapl_get_item`에 선택적 `compact=false` 인자를 추가했다. 생략과 false는 기존 전체 응답을 그대로 반환한다. true는 보존된 canonical 필드로 기존 renderer가 body를 정확히 재현할 때만 중복 body를 제외한다. finding 본문, raw text, 사용자 내용, 다른 필드와 오류는 보존한다. 누락·비문자열 필드, 공백 차이, 오래된 body는 축약하지 않는다.
- compact 검증 응답이 경고 세 개 뒤의 차단 오류를 가릴 수 있던 문제를 수정했다. 모든 dictionary 형태 오류를 먼저 유지하고 경고만 제한한다. `omitted_issue_count`로 생략 수를 알린다. 기존 validator의 정상 출력 형식을 대상으로 한다.
- 코드 모드는 필요한 도구 설명·스키마를 함께 발견하고 유지된 정의를 재사용하도록 명시했다. 이미 보유한 동일 서버 안내만 중복 출력에서 제외하며, 컨텍스트 소실·변경 시 재조회한다. 확정된 호출도 순차 await와 결과·검증 확인을 지켜야 한다. 승인·원문 확인·실행 검증·dispatch 조건을 생략하거나 결과를 예상해 완료 처리할 수 없다. finish 후 기억 검토를 확인하고 archive한다.
- 도구 29개를 유지했다. 새 compact 인자만 제외한 기존 도구 계약·스키마 해시는 기준본과 같다. DB, 검색, 설정 저장, 승인·dispatch·복구 구현은 변경하지 않았다.

간결 조회는 실제 DB의 plan/task/finding, 아카이브 기록, 사용자 본문을 사용해 full → compact → full 순서로 검증했다. 렌더러 일치, 기본 응답·오류 동일성, 원본 payload 불변과 비정상 입력도 검사한다.

정적 측정

같은 호스트와 probe를 사용한 기준·후보 비교다. 문자 수는 토큰 수나 최대 컨텍스트 사용률이 아니다.

대표 compact 응답은 전체 응답보다 32.6% 작고, 제외한 body를 재구성하면 전체 응답과 정확히 같다. 이 비율은 해당 합성 fixture의 결과로 일반적인 기록 전체에 적용할 수 없다. 안전한 연속 실행 규칙을 추가해 전체 진입 응답은 약 3.0% 커졌다. 전체 정책의 정적 길이 검사 상한도 12,500자에서 13,000자로 조정했으며, 반복되는 초기 진입 안내의 900자 상한은 유지한다. 실제 대화에서 왕복·출력 감소가 이 비용을 상쇄하는지 후속 검증해야 한다.

대화 평가기 보강과 남은 실행

기존 8조건을 유지하고 다음 세 조건을 추가했다.

- `memory_reuse`: 저장된 기억 회상, 정확한 원문 전달, 원문 확인 후 실제 bytes 동일성 검증, 정확한 revision의 memory_uses. 축약된 task 원문도 canonical 필드로 재구성해 검증한다.
- `batch_recovery`: 실제 spawn 전에 중단된 manifest를 seed하고, 기존 execution IDs 조회와 정확한 batch 복구, 같은 task의 순차 실행 전환·정산을 확인한다. 중단 상태를 준비한 실험이며 실제 spawn 오류를 주입한 것으로 표시하지 않는다.
- `context_loss`: 첫 실제 세션이 plan/task를 저장하고 두 번째 독립 Codex 세션이 같은 기록을 복원한다. 정책 전체 재진입, record ID·본문의 연속성과 실행 전 조회를 검사한다. 실제 자동 compaction 테스트와 구분한다.

빈 성공 응답, 누락된 정책 bundle, 원문 없는 조회, 원문 이전 검증 시작, 출력만 하는 검증 문구, 약한 부분 문자열 검사, 교체된 execution ID, 복구 이전 편집, 겹친 순차 작업과 실행 후 상태 조회를 거부하는 음성 검사를 추가했다. 명령 분석은 fixture에 한정되며 새로운 동등 표현은 원본 trace 검토가 필요하다.

계측은 root session만 집계하고 최대 단일 입력·누적 입력·cached input·exec/discovery 호출 및 탐색 포함 응답 bytes를 분리한다. 모델 요청 수는 0 초기화와 metadata 보강을 제외한 누적 usage 갱신에 근거한 추정치다. 계정 rate-limit 정보는 저장하지 않는다.

승인 후 11조건 각각 새 Morae Box 3회 이상과 edit/memory_reuse의 기준본 비교를 실행해야 한다. 제품 프롬프트를 고치면 같은 최종본으로 다시 반복한다. 판정기만 수정할 때는 원본을 보존하고 재검사와 음성 검사를 수행한다. 결과 없는 항목은 통과로 집계하지 않는다.

환경·적용

Morae/libkrun, Python 3.11.2, MCP 2.0.0, pytest 9.1.1을 사용했다. 초기 복사 대상 디렉터리 충돌과 Ruby 미설치로 발생한 준비·패키징 검사 오류는 최종 통과 표본에서 제외했다. 복사 대상이 없는 의존성 seed와 Ruby 3.1.2를 준비한 뒤 새 VM 세 곳에서 전체 검사를 다시 통과했다.

현재 연결된 Codex MCP는 Homebrew 설치본을 사용한다. 저장소 변경이 기존 서버 프로세스에 자동 적용됐다고 간주하지 않았다. 실제 대화 시험은 각 Box에 명시한 제품 소스를 로드하고 해시·정책 revision을 확인하도록 준비했다. 사용자 전역 설치와 현재 연결은 변경하지 않았다.
