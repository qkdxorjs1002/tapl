# 참고 벤치마크

[문서 홈](../README.ko.md) · [English](benchmarks.md)

작성 상세도 선택에 참고할 수 있도록 공개된 측정 조건, 집계값과 한계를 정리합니다. 아래 수치는 재현을 보장하는 성능 목표가 아닙니다.

<a id="authoring-detail-benchmark"></a>

## 측정 조건

2026-10-29~30에 동일한 SQLite 롤백 버그 수정을 조건별 5개 독립 Morae VM에서 측정했습니다(총 20회).
TAPL `2.14.0-beta3`(`2.14.0b3`), Codex CLI `0.159.0`, 모델 `gpt-6.1-sol`, 추론 `high` 조건입니다.
작업 요청과 초기 코드는 같으며, TAPL 조건은 Strict 모드·enforcing hook을 켜고 recall·SubAgent를 껐습니다.
`agents-history`는 TAPL MCP·hook 없이 AGENTS.md 정책으로 RUN·PLAN·TASK·필요한 FINDING·상태 이력을
파일로 기록하는 비교군이며 제품 설정값이 아닙니다.
20개 모두 기능 검사를, TAPL 15개는 핵심 워크플로 검사를, 파일 기록 5개는 구조 검사를 통과했습니다.
파일 기록의 요구사항과 절차 예외는 아래 [정책·감사 발췌](#authoring-detail-file-history)에 정리했습니다.

측정한 beta3의 당시 기본값은 `precise`였습니다. 현재 기본값 `auto`와 모드별 자동 선택은 이 비교의 측정 대상이 아니므로 이 결과로 성능을 판단할 수 없습니다.

아래는 **조건별 5개 표본의 중앙값**이며, 괄호 안 증감률은 **`tapl + precise` (beta3 비교 기준) 대비**입니다.
PLAN·TASK 개수는 관측값이며 제한이 아닙니다. N/A 지표에는 증감률을 표시하지 않습니다.

| 비교 조건 | 관측 PLAN / TASK | 본문 문자 | 작성 인자 bytes | 전체 입력 토큰¹ | 출력 토큰 | 소요 시간² |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| `tapl + precise` (beta3 비교 기준) | 1 / 3 | 2,227 | 5,257 | 348,705 | 5,607 | 167.7초 |
| `tapl + normal` | 1 / 2 | 1,646 (−26.1%) | 2,758 (−47.5%) | 347,300 (−0.4%) | 4,638 (−17.3%) | 129.9초 (−22.6%) |
| `tapl + minimal` | 1 / 1–2 | 1,290 (−42.1%) | 2,168 (−58.8%) | 364,056 (+4.4%) | 4,031 (−28.1%) | 125.0초 (−25.5%) |
| TAPL 미사용 + AGENTS 기록 (`agents-history`) | 1 / 3–4 | 6,323 (+183.9%) | N/A | 210,919 (−39.5%) | 9,077 (+61.9%) | 184.9초 (+10.3%) |

¹ 입력은 캐시 포함 값입니다. 각 표본의 `input_tokens - cached_input_tokens`로 계산한 신규 입력 중앙값은
정확하게 / 보통 / 최소 / AGENTS 기록 순서로 **30,881 / 44,706 / 39,160 / 16,780**입니다. 따로 집계한 중앙값이므로 열의 중앙값끼리
뺀 결과와 다를 수 있습니다. 가격이나 청구 금액은 계산하지 않았습니다.

² 소요 시간은 Codex 세션 시작부터 종료까지이며, 모델 응답·도구 호출·세션 내 검증을 포함합니다.
VM 준비와 세션 종료 후 결과 감사는 제외합니다. 조건별 표본의 시간 범위가 서로 겹치고
서버 부하·캐시 효과를 통제하지 않았으므로, 이 중앙값으로 일반적인 속도 우위를 단정할 수 없습니다.

본문 문자는 TASK 완료·검증 결과를 포함한 최종 PLAN·TASK Markdown의 문자 수입니다.
작성 인자 bytes는 완료된 `tapl_apply_plan`·`tapl_create_task` 호출의 인자를 동일한 UTF-8 JSON 직렬화 기준으로
합산한 값이며 빈 `{}`도 포함합니다. 다른 도구는 집계하지 않습니다. 문자·바이트는 토큰 수와 다릅니다.
입력·출력 토큰은 코드 수정·추론·도구 검색·검증까지 포함한 **전체 대화**의 사용량입니다.
N/A를 측정값 0으로 해석하지 않습니다. 파일 기록의 본문은 첫 ID·제목 헤딩을 제외하며,
RUN·FINDING·HISTORY 크기는 별도로 보존합니다. MCP 인자·typed/custom JSON 지표는 N/A입니다.

파일 기록의 PLAN·TASK 본문은 정확하게보다 길었습니다(6,323자 대 2,227자).
정책 문구·서식·작업 분할·실제 기록 내용도 다르므로 토큰 차이를 MCP와 파일 쓰기 방식만의 효과로 단정할 수 없습니다.
이 AGENTS 정책은 TAPL의 강제 기능이나 제품 전체 기능을 복제하지 않습니다.

이번 작업에서 보통·최소의 기록량과 출력 토큰 중앙값은 줄었지만 전체 입력의 뚜렷한 절감은 관찰되지 않았습니다.
제공자 측 입력 캐시, 도구 검색, 추가 회귀 테스트가 표본마다 달랐습니다. 한 합성 작업의 옵션별 5회 반복만으로
일반적인 품질·속도·비용을 보장할 수 없습니다.
AGENTS 기록 표본은 기존 TAPL 15개와 함께 무작위 배정하지 않고 나중에 수집했으므로
시간·캐시 효과와 조건 효과를 분리할 수 없습니다. 이 수치로 TAPL의 워크플로 기록이 주는 가치를 판단할 수는 없습니다.

## 파일 기록 정책·감사 발췌

AGENTS.md 정책은 고정 개수·길이 제한 없이 다음을 요구했습니다.

- 구현 전에 요청·모드·승인을 담은 RUN, 요구사항·접근법·범위·실행 순서·위험·롤백·검증을 담은
  확정 PLAN, 작업·검증을 담은 Pending TASK를 작성합니다.
- 각 TASK는 실행 직전에 시작하고 검증 후 완료합니다. 시각을 포함한 상태 이력을 남기며 이전 행을
  보존하고, 필요한 발견 사항에는 출처와 영향을 기록합니다.
- 모든 TASK를 정리하고 검증 결과를 기록한 뒤 RUN을 아카이브하며, 기록 파일과 참조를 보존합니다.

최종 Markdown과 시간순 도구 실행 기록을 검토한 결과입니다.

| 검사 | 요구사항을 충족한 표본 |
| --- | ---: |
| 기록 구조 검사 | 5 / 5 |
| 구현 전 PLAN·TASK 작성 | 5 / 5 |
| 아카이브 전 모든 TASK 정리 | 1 / 5 |
| HISTORY의 이전 행 보존 | 4 / 5 |
| 관찰된 절차 예외 없음 | 1 / 5 |

4개는 마지막 TASK 완료 전에 아카이브했고, 그중 1개는 시각 정정 중 HISTORY의 이전 행도 대체했습니다.
구조 검사 통과와 모든 절차 요구의 준수는 구분해야 하며, 관찰 결과는 강제 실행의 보장이 아닙니다.
집계값과 이 발췌만 공개하며, 원문 대화·개별 기록·실험 산출물은 비공개로 보관합니다.

## 측정한 작성 수준 적용 예제

```sh
taplctl config get workflow.authoring_detail
taplctl config set workflow.authoring_detail normal
```

이 명령은 이후 작업의 작성 정책을 선택합니다. 벤치마크를 다시 실행하거나 위 결과를 재현하는 명령은 아닙니다. 설정 선택·검증과 기본값 복원은 [작성 상세도](../guides/authoring-detail.ko.md)를 참고하세요.
